# سامانه CMMS (مدیریت نگهداری و تعمیرات)

سامانه مدیریت نگهداری و تعمیرات پیشگیرانه برای مجتمع‌های تله‌کابین، شامل مدیریت
سلسله‌مراتب مجتمع/خط/ایستگاه/تجهیز، دستورکارها و بازرسی‌ها، ثبت توقفات (Downtime)،
پایش وضعیت (Condition Monitoring)، گزارش‌گیری و مدیریت کاربران با کنترل دسترسی
مبتنی بر نقش (RBAC).

## اجرا در محیط توسعه

پیش‌نیاز: Node.js نسخه ۱۸ به بالا.

```bash
npm install
cp .env.example .env   # و JWT_SECRET را با یک مقدار تصادفی پر کنید
npm run dev
```

سرور روی `http://localhost:3000` بالا می‌آید (Vite در همان سرور Express به‌صورت
middleware اجرا می‌شود).

## اجرا در محیط Production

```bash
npm run build
NODE_ENV=production JWT_SECRET=<یک مقدار تصادفی و طولانی> npm start
```

نکات مهم قبل از دیپلوی:
- **`JWT_SECRET` را حتماً تنظیم کنید** — بدون آن سرور در حالت production بالا نمی‌آید.
- در پشت HTTPS اجرا کنید تا کوکی امن (`secure`) به‌درستی کار کند.
- دیتابیس به‌صورت فایل JSON در مسیر `data/db.json` نگهداری می‌شود. برای استفاده
  واقعی و مقیاس‌پذیر، توصیه می‌شود آن را با یک دیتابیس واقعی (PostgreSQL/SQLite
  از طریق Prisma یا Drizzle) جایگزین کنید.

## کاربران پیش‌فرض (فقط برای محیط توسعه/دمو)

| نام کاربری        | رمز عبور | نقش              | محدوده دسترسی                  |
|--------------------|----------|-------------------|----------------------------------|
| `admin`             | `123`    | SUPER_ADMIN       | همه‌ی مجموعه‌ها                 |
| `complex_admin`     | `123`    | COMPLEX_ADMIN     | مجموعه توچال                    |
| `line_supervisor`   | `123`    | LINE_SUPERVISOR   | خط ۱ تله‌کابین توچال            |
| `station_operator`  | `123`    | STATION_OPERATOR  | ایستگاه ۱ خط ۱ توچال            |

کاربران با نقش `LINE_SUPERVISOR` / `STATION_OPERATOR` پس از ورود، به‌صورت خودکار
مستقیماً به داشبورد مجموعه/خط خودشان هدایت می‌شوند و صفحه‌ی انتخاب مجموعه/خط را
نمی‌بینند. **این رمزهای پیش‌فرض را پیش از استفاده‌ی واقعی حتماً تغییر دهید.**

## معماری

- `server.ts` — سرور Express + Socket.IO + REST API (احراز هویت JWT در کوکی httpOnly)
- `src/` — فرانت‌اند React + Vite + Tailwind
- `data/db.json` — ذخیره‌سازی داده (ساخته می‌شود در اولین اجرا)
- `uploads/` — تصاویر و فایل‌های اکسل آپلودشده

## تغییرات امنیتی اعمال‌شده

- تمام مسیرهای نوشتن/حذف API اکنون پشت احراز هویت (JWT) و کنترل دسترسی نقشی قرار دارند.
- توکن JWT در کوکی `httpOnly` ست می‌شود (قبلاً هرگز واقعاً استفاده نمی‌شد).
- `JWT_SECRET` از متغیر محیطی خوانده می‌شود، نه هاردکد در کد.
- رمز عبور مجتمع‌ها با bcrypt هش می‌شود.
- ثبت لاگ فعالیت‌ها از کاربر تأییدشده (JWT) خوانده می‌شود، نه از هدرهای قابل‌جعل کلاینت.
- محدودیت نوع و حجم فایل روی آپلود تصویر/اکسل اعمال شده است.
- داده‌ها روی دیسک ذخیره می‌شوند و با ری‌استارت سرور از بین نمی‌روند.
